# 迁移分层架构

简体中文 | [English](architecture.md)

把完整 Android 迁移当作文件复制会使回滚和升级变得脆弱。本工具集使用六个可以独立验证的层。

| 层 | 示例 | 恢复规则 |
| --- | --- | --- |
| 硬件身份 | product、SoC、存储容量 | 只比较，绝不克隆设备标识 |
| 固件/ROM | 启动链、动态分区、vendor firmware | 只使用为 `fuxi` 构建的包，并验证哈希和槽位拓扑 |
| Root 运行层 | 修补后的 boot/init_boot、Magisk 模块 | 必须针对目标精确构建安装，并单独启动测试 |
| Framework Hook | LSPosed/Vector 模块与作用域 | 先恢复模块 APK；确认目标包存在后再应用作用域 |
| 应用与用户数据 | APK、应用数据库、共享存储 | 优先使用官方迁移/导出；不得用钱包/TSM 私有数据替代目标 eSE 配置 |
| 设置与界面 | secure/global/system 设置、输入法、启动器 | 最后应用，并保留前后导出与回滚副本 |

## 升级规则

基础 ROM 更新必须与兼容 overlay 分离。每次 ROM 更新后：

1. 重新采集设备清单和分区指纹。
2. 针对新 commit 重建 boot/内核工件。
3. ABI 或 Android 版本变化时，先在不启用可选模块的状态下启动。
4. 逐个恢复限定作用域的模块并记录验证证据。

绝不提交原始设备导出；仓库中只保存脱敏模板和工件哈希。
